Bernoulli Naive Bayes - Application

Problem Description

This application classifies the risk level of a driver based on observable driving behaviors. Instead of continuous values, the model evaluates whether risky behaviors are present (1) or absent (0), such as overspeeding or phone usage while driving.

Dataset Explanation

The dataset consists of binary variables representing driver behaviors. Each feature indicates whether a risky action occurred (1) or not (0). The target variable defines whether the driver is classified as high risk or low risk.

Input Variables and Target Variable

  • Input variables: overspeeding, night driving, phone usage, aggressive braking
  • Target variable: accident risk (1 = high risk, 0 = low risk)

Data Preparation

The dataset is already structured in binary format, meaning each feature takes values of 0 or 1. This makes it directly compatible with the Bernoulli Naive Bayes model.

No normalization is required, since all variables share the same scale. The dataset is split into training and testing sets to evaluate model performance.

This preprocessing step ensures that the model can learn meaningful patterns from consistent and well-structured input data.

Model Training Process

The Bernoulli Naive Bayes model calculates the probability of each class given the observed features, assuming independence between them. It selects the class with the highest probability as the prediction.

Prediction Flow

The Bernoulli Naive Bayes model follows a probabilistic pipeline:

  • Step 1: Evaluate each feature as present (1) or absent (0)
  • Step 2: Compute probability of each feature given the class
  • Step 3: Multiply probabilities assuming independence
  • Step 4: Select class with highest posterior probability

This process allows the model to efficiently classify driver risk based on simple binary inputs.

Interpretation of Results

The Bernoulli Naive Bayes model demonstrates solid performance in classifying driver risk based on binary behavior indicators.

Precision indicates that when the model predicts a driver as high risk, it is usually correct. Recall shows that the model successfully identifies most of the actual high-risk drivers.

Some classification errors are expected due to the independence assumption, but overall the model remains reliable and interpretable.

The ROC curve confirms that the model maintains a good balance between sensitivity and specificity.

In safety-related applications, recall is particularly important because failing to detect a high-risk driver could lead to serious consequences. Therefore, the model prioritizes identifying risky cases even if some false positives occur.
